# 《远方来信》设计推演记录

> 本文记录编码前的规则级与故事级演练。它能证明合同在抽象状态机中可继续，不代表 AI 文案、真实后端、真实玩家理解或最终画面已经通过。

## 1. 推演目标

优先验证此前 RPG 最常见的失败：推荐选项打断现场、地点漂移、休息无收益、工资不入账、未经同意扣钱、精力归零死局、相同动作循环、共享动作重复提交，以及其他玩家改变世界后旧选择继续显示。

## 2. 第一组：十条确定性规则路径

执行：`node _design/route-simulator.mjs`

结果：10/10 通过。

| 路径 | 验证结果 |
|---|---|
| 直达路线中出现断桥 | 现场事件出现后，所有旅行选项退出；解决后才继续抵达 |
| 途中短休 | 精力增加，原 `journey_id` 保留，随后能抵达原目的地 |
| 工作报酬与住宿支出 | 收到 9、明确支付 5 后余额精确为 12 |
| 精力归零 | 进入确定恢复，恢复后原旅程仍存在 |
| 重复公共修路 action ID | 世界版本与游标只增加一次 |
| 接力信件回执 | 先进入个人行囊并回读，之后才确认公共回执 |
| 离线期间道路变化 | 重连更新公共版本，不覆盖个人位置或私人状态 |
| 完全不追主线 | 线索为 0 时仍可跨区域自由探索 |
| 从现场明确撤离 | 产生关系代价，事件结束，路线状态仍可继续 |
| 用户生成沿途地点 | 新地点固定挂在生成它的父路线，不漂移到其他区域 |

## 3. 第二组：四类玩家的长流程随机推演

执行：`node _design/campaign-simulator.mjs`

方法：主线型、探索型、帮助型、谨慎型各 50 次；每次 80 个抽象行动，共 200 条旅程、16,000 个行动。每步检查：至少一个可走选项、选项不超过五个、现场事件期间无旅行选项、地点属于地图、数值不越界、同一动作不连续空转超过三次、事件最长三步必须转向或结束。

### 第一次运行：失败

帮助型玩家连续购买同一份补给。动作只扣钱，没有改变购买需求，因此形成“看似成功但世界没有前进”的软循环。

修订：购买必须生成具体入包物；同类路用补给最多携带 2 份，达到上限后该购买选项消失；旅行消耗后才可再次购买。

### 第二次运行：通过但节奏偏重

200 条旅程全部保持可玩，但短休占行动比例约三至四成。说明恢复量太低，玩家会频繁执行机械休息。

修订：短休由 8–16 调整为 16–24；抽象模型取中值 +20。休息仍推进 45–90 分钟，并保留旅程和现场上下文。

### 第三次运行：规则通过

- 200/200 条旅程完成 80 步，无死路、无越界、无同按钮扣资源循环。
- 探索型 50/50 都访问了 7 个区域。
- 其他三类玩家每次访问 5–7 个区域，说明没有被单一路线锁住。
- 所有现场事件在规则规定的三步内解决、转向或明确撤离；少量运行在第 80 步恰好生成新事件，属于采样截断，并非无解状态。
- 休息比例降至约 27%，仍需在真实垂直切片中观察是否过密；暂不继续用纯抽象模型调数值。

## 4. 故事级演练

### A. 主线直行玩家

玩家从雨港选择草原—盆地—高原—白脊。途中遇到断桥时，只能修桥、确认替代通道或承担后果撤退，不能直接出现白塔选项。到达白脊时只有 5 条线索，因此可以进入群岛生活区，但白塔最终回应保持关闭，并明确给出仍可调查的已知证据来源。

结论：远方目标可见，但不能把探索玩家挡在整片终局区域之外；只锁最终回应，不锁群岛。

### B. 完全偏离主线的探索玩家

玩家拿到未来来信后去湖林，在疗养院、林间渡口和矿镇连续处理地方故事，三次访问都不增加主线线索。地图、人物关系、工作报酬和生成地点仍持续增长，返回主线时旧人物与路线保持。

结论：主线不是唯一内容源；地方事件必须有自己的完成与回访价值。

### C. 正在发生的袭击

玩家刚带回一名偷窃邮袋的人，他的同伴赶到要求放人。选择“和同行者商量”后，袭击者仍作为 `active_incident` 参与下一回合；商量只能改变应对方案，不能让他们从故事里消失。下一组选项必须点名谈判、保护证物、求助或撤离。

结论：讨论、观察和休息都是事件内动作，不是清空事件的万能跳板。

### D. 休息与旅程

玩家在开往湖林的渡船上靠窗休息。结果恢复精力并推进船程，下一选项围绕即将靠岸、甲板上的争执或继续休息；不会出现找短工、吃热饭或去公共休息处等地点不成立的固定菜单。

结论：恢复动作必须从当前交通方式和环境生成后续，而不是调用全局生活菜单。

### E. 自由输入未知地点

玩家输入“我要去北边一座没人知道的玻璃车站”。系统判断当前在雨港—湖林路线，允许把它作为沿途传闻调查；首次发现后生成稳定地点 `rain-coast__lakewood__glass-roof-stop`。如果玩家仍在未解决的码头火灾中，则先说明无法立即离开，并提供扑火、求助或明确放弃现场后出发。

结论：自由输入扩大世界，但不能绕开当前事件或直接写入公共世界。

### F. 另一位玩家抢先改变道路

玩家看到“乘最后一班渡船”并提交，但权威世界显示另一位玩家已使用最后一桶燃料让船离港。旧选择被作废，系统说明具体变化，提供帮助寻找燃料、等待下一班、改走盐沼堤道；不会再次显示同一个渡船按钮。

结论：共享冲突必须生成基于新事实的替代方案，而不是通用恢复话术。

### G. 提交成功但响应丢失

玩家贡献修桥后网络断开。客户端保持原 action ID 为未知结果；重连按 cursor 找到已提交事件，显示修桥成功，不再次扣物资。若场景文案生成失败，使用“你交出的木料已登记，桥面加固了一段”的确定性事件文案。

结论：权威提交与故事生成分离；文案失败不能回滚世界或恢复旧按钮。

### H. 世界很安静

测试世界没有其他活跃玩家。所有个人路线、12 条线索和最终回应仍可完成；公共工程保持可选，并显示真实贡献而非伪造其他玩家活动。

结论：多人提升世界质感，但不成为内容容量和通关的依赖。

## 5. 当前结论与未验证项

已在设计层确认：地图连通、现场优先、休息保旅程、资金需同意、数值有恢复、自由探索不依赖主线、共享动作幂等、公共回执可恢复。

仍需垂直切片验证：

1. 真实 AI 是否能持续生成足够具体、不会打断现场的推荐选项。
2. 8–15 分钟内路线、现场与抵达三层节奏是否自然。
3. 30 个地点在移动端地图上是否让人感到广阔而不是拥挤。
4. 第一/第三人称均衡导演的真实出图质量与角色身份稳定性。
5. 两个真实账户的版本冲突、接力信件、回执与离线重连。
6. 新玩家是否能复述目标、反复行动和什么算进展；当前标记为 `comprehension unverified`。
7. “吸引力与心流”仍属于设计假设，只有真实玩家行为和主观反馈才能验证，不能由这批自动化宣称通过。

## 6. 前五分钟专项修订

新增要求后，原先的六拍开场被判定过慢：玩家要先经历多个作者节拍才能产生第一次有后果的输入。切片改为四拍，每拍只引入一个可感知事实，并把第一次判断提前到约 20–45 秒。

三个第一次判断分别产生线索、人物承诺和共享道路痕迹；它们不只是三种措辞。三条路径都在 120 秒内进入两条具体路线的取舍，并在 300 秒内获得第一次可见回报。自动化只能验证时序和状态变化，不能证明玩家主观上已经觉得好玩。
